# KXC Relay 算子注册指南

本文档详细说明了如何在 KXC 编译器中添加新的 Relay 算子。遵循此规范可以确保算子能够被编译器前端、Pass 优化器和后端 CodeGen 正确处理。

## 1. 目录结构

为了保持代码整洁，建议按照算子类别将注册代码分散在 `src/relay/op` 目录下：

```
src/relay/op/
├── nn/                 # 神经网络相关算子 (Convolution, Pooling, Activation)
│   ├── convolution.cc
│   ├── pooling.cc
│   └── activation.cc
├── tensor/             # 张量变换算子 (Reshape, Split, Concat)
│   ├── transform.cc
│   ├── math.cc
│   └── reduce.cc
├── image/              # 图像处理算子 (Resize, Crop)
└── algorithm/          # 排序、TopK 等算法
```

## 2. 注册流程 (Step-by-Step)

### 第一步：定义属性结构体 (C++ Header)

如果算子有配置参数（如 `strides`, `axis`, `epsilon`），首先需要在 C++ 中定义一个继承自 `Attrs` 的结构体。

**位置**: `include/relay/op.h` (或者新建 `include/relay/attrs/nn.h` 并在 `op.h` 中包含)

```cpp
// include/relay/op.h

// 1. 定义 Node (存储数据)
class SoftmaxAttrsNode : public BaseAttrsNode {
public:
    int axis;
    void SerializeCanonical(CanonicalAttrWriter& writer) const override {
        writer.Add("axis", axis);
    }
    
    // 必须实现 GetTypeId
    const TypeIndex GetTypeId() const override { return kKXC_OBJECT_TYPE + 20; }
};

// 2. 定义 Wrapper (RefCounting 接口)
class SoftmaxAttrs : public Attrs {
public:
    using Attrs::Attrs;
    
    // 定义静态 Create 方法，设置默认值
    static SoftmaxAttrs Create(int axis = -1) {
        SoftmaxAttrsNode* node = new SoftmaxAttrsNode();
        node->axis = axis;
        
        SoftmaxAttrs attrs;
        attrs.object_ = node;
        if(attrs.object_) attrs.object_->IncRef();
        return attrs;
    }
    
    // 方便访问成员的运算符重载
    const SoftmaxAttrsNode* operator->() const { 
        return static_cast<const SoftmaxAttrsNode*>(object_); 
    }
};
```

`SerializeCanonical` 是编译身份契约的一部分：必须按 schema 顺序写入每个
字段且不得遗漏或重复。字段名、字段类型和字段值共同参与 compilation-unit
hash；无字段 attrs 应使用 `KXC_DEFINE_SIMPLE_ATTRS`。

### 第二步：注册算子 (C++ Source)

在对应的 `.cc` 文件中使用 `KXC_REGISTER_OP` 宏进行注册。

**位置**: `src/relay/op/nn/activation.cc`

```cpp
#include "../../../include/relay/op_macros.h"
#include "../../../include/relay/relay.h"

namespace kxc {
namespace relay {

KXC_REGISTER_OP(nn_softmax)
    // 1. 描述算子功能
    .describe(R"doc(Softmax activation function.

Computes the softmax function: exp(x) / sum(exp(x)).
)doc")
    
    // 2. 设置输入数量
    .set_num_inputs(1)
    
    // 3. 定义输入参数 (名称, 类型, 描述)
    .add_argument("data", "Tensor", "The input tensor.")
    
    // 4. 绑定属性结构体 (关键!)
    // 这里的 "SoftmaxAttrs" 必须与第一步定义的类名对应（或者是 TypeKey）
    // 编译器前端会使用这个 Key 来查找如何解析 Python 参数到 C++ 结构体
    .set_attr<std::string>("TAttrs", "SoftmaxAttrs");

} // namespace relay
} // namespace kxc
```

## 3. 注册 API 详解

### `KXC_REGISTER_OP(OpName)`
创建一个新的算子注册条目。`OpName` 应该是全局唯一的标识符，通常使用 `domain.op` 格式（如 `nn.conv2d`），但在 C++ 变量名中我们使用下划线（如 `nn_conv2d`）。

### `.describe(const std::string&)`
提供算子的文档字符串。支持多行字符串 (`R"doc(...)doc"`)。这会被用于生成 Python 文档。

### `.set_num_inputs(int n)`
设置算子需要的输入 Tensor 数量。
*   对于变长输入（如 `concat`），通常设置为 1（输入为一个 Tuple）。

### `.add_argument(name, type, description, is_optional, default_value)`
描述算子的输入参数。
*   `name`: 参数名 (如 "data", "weight")
*   `type`: 参数类型 (如 "Tensor", "Tuple")
*   `description`: 参数说明
*   `is_optional`: 是否可选 (bool)
*   `default_value`: 默认值的文本描述 (string)

### `.set_attr<T>(key, value)`
设置算子的元数据。
*   **"TAttrs"**: 最重要的属性。它的值应该是对应的 C++ Attrs 类名字符串。这告诉系统：“这个算子除了输入 Tensor 外，还需要解析这些配置参数”。
*   **"TOpPattern"**: (可选) 算子模式（如 `kElemWise`, `kCommReduce`），用于算子融合策略。
*   **"FInferShape"**: (可选) 形状推断函数。
*   **"FInferType"**: (可选) 类型推断函数。

## 4. 最佳实践

1.  **必填 vs 选填**: 将所有 Tensor 输入定义在 Attributes 之前。Attributes 应该有合理的默认值。
2.  **复用属性**: 如果多个算子共享相同的配置（如 `MaxPool2D` 和 `AvgPool2D`），可以复用同一个 Attrs 结构体。
3.  **文档**: 务必编写清晰的文档字符串，说明输入的 Shape 要求（如 `NCHW` vs `NHWC`）。
4.  **模块化**: 不要把所有算子都写在一个文件里。按功能分类存放。

## OperatorSpec registration contract

Operator registration is split into two APIs:

- `Op::Register(name)` creates a registry entry and is used by `KXC_REGISTER_OP`.
- `Op::Get(name)` only looks up an already registered operator and throws for
  every unknown name, including namespaced control operators.
- `Op::Register(OperatorSpec)` explicitly registers metadata-only control or
  external operators at their owning layer.

The existing fluent registration style remains supported. The registry derives a
metadata-only `OperatorSpec` from `.set_num_inputs`, `.add_argument`, `TAttrs`,
`FInferType`, `FRelayToTE`, and `FRelayToTEMulti`. Do not store function objects,
TE tensors, TIR nodes, or backend handles inside `OperatorSpec`; store only
stable keys.

Fixed-arity operators use `.set_num_inputs(n)`. Variable-arity operators must
use `.set_input_arity_range(min_inputs, max_inputs)`; `-1` without an explicit
range is not a complete independent-compilation contract.

External/control operators must be registered explicitly with a complete spec.
Lookup never infers behavior from the operator name and never creates a registry
entry. New public compute operators must also be declared in
`test/relay_op_contract.json`.

When adding or changing an operator, update the JSON contract first. Required
fields include `schema_version`, `category`, arity, `attrs`, `output_arity`,
`type_relation_key`, `effect`, `deterministic`, `alias`, `lowering`,
`lowering_key`, `ffi`, `tests`, and `onnx_ops`.
